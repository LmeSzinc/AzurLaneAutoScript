# PR #1 — 分支 `commission-skip`

## 标题（复制下面一行）

```
[Commission] 无法开始的委托直接跳过，不再重启游戏
```

## 正文（复制下面整段）

## 优化点

「开始」按钮点不亮的委托（典型是**高级战术研究**这类需要 100 级舰船的委托：
「推荐」只会随便填 Lv.1 的船，条件永远不满足），原逻辑会一直重试 →
`GameStuckError` → **重启整个游戏**，正在跑的其他委托全部作废。

改成**放弃这一条委托，交给调用方去处理下一条**。三个判据，谁先到算谁：

| 常量 | 值 | 触发条件 |
| --- | --- | --- |
| `COMMISSION_SKIP_AFTER_RECOMMEND` | 5s | 点了「推荐」、舰船已填入，但「开始」仍是灰色 |
| `COMMISSION_SKIP_TIMEOUT` | 90s | 单条委托的绝对上限 |
| `COMMISSION_SKIP_MAX_RECOMMEND` | 3 次 | 连点 3 次「推荐」仍不行（就是官方注释里那个列表闪烁 bug） |

另外加了两处收尾：

1. **会话级黑名单** `COMMISSION_SKIP_LIST`。被判定为开不了的委托，本次 Alas
   运行期间不再尝试；重启 Alas 清空，所以凑齐船以后还能再试。
2. **黑名单必须在 `_commission_check()`（选之前）排除**，不能等选中之后再过滤。
   选中之后再排除会白白占掉名额，导致排在后面的可用委托递补不上来——实测
   出现过「3 个委托位空着 3 小时」的情况。

## 作用

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 等级不够的委托 | 重试 16 秒 + **重启游戏** | 5 秒跳过，且**一次都没点过开始键** |
| 正常委托 | 0.6 秒启动 | 不变 |

## 验证

- 离线 8 个用例全过（等级不够 / 正常委托 / 未点推荐就进船坞 / 选错委托）
- **实机复核过**（2026-09-14 12:33 那次）
- ⚠️ 其中「`_commission_check()` 里排除黑名单」这一处是复核之后才加的，
  **尚未实机验证**，要等下一次委托刷新才看得到

## 风险

被误判为「开不了」的委托会被跳过一整轮（Alas 重启后恢复）。三个判据都要求
「推荐」已点且「开始」持续灰，正常委托不会命中。
